Most of these assertions are about refusal. A 200 proves an endpoint answered. The 401 on POST /api/strategies proves a stranger cannot spend the AI budget on a child's observation, and the 404 on an unknown guardian code proves the server gives one answer for never-existed, already-used and withdrawn — because telling them apart would tell a stranger which codes are real.

Held back, and why

The Row-Level Security suite was not run. Thirty-six files in tests/rls sign in as real users against the one shared Supabase project. Each builds a school, five people and some students, and clears anything matching the test naming convention first so it survives a crashed previous run. Two people running it at once means one person's setup deletes the other's world mid-assertion, and it surfaces as a broken-looking suite rather than a busy database — so CONTRIBUTING.md §2 asks for a message in the group chat before anybody starts. No message was sent, so it was not started.

  • npm test — the full suite, 36 RLS files plus the 6 unit files above. Takes about six minutes. Watch the duration, not the tick: a database job that finishes in under a minute is skipping, and the green tick means nothing.
  • npm run security-check — four suites, including the anonymous attack surface. Not run here; it also reaches the shared project.
  • npm run storage-check — file storage policies, signing in as real people. Same reason.

All three run in CI on every pull request, which is where they are meant to be read from.
