# MiZanova — Site map

Every URL the application serves, as of 2026-09-15.

Generated by reading the two files that define routing. If you change a route,
change it there and update this document in the same commit:

- `src/App.tsx` — public, auth, account and detail routes; the `BUILT_SCREENS`
  and `DETAIL_ROUTES` maps.
- `src/lib/roles.ts` — `ROLE_CONFIG`: each role's base path and sidebar. **Role
  routes are generated by walking `config.nav`**, so a sidebar item and its
  route cannot drift apart — and a `BUILT_SCREENS` entry with no matching nav
  item builds no route at all.

**Status: every nav item in every role now renders a real screen.** No
`Placeholder` remains on any generated route.

## 4. Role sections

Each role's whole section is wrapped in `ProtectedRoute allow={[role]}` →
`AppShell`. **Order of refusal** (`src/components/ProtectedRoute.tsx`):

1. No session → `/login`, remembering where you were going.
2. Password but no second factor yet → `/verify-2fa`.
3. Signed in, wrong role → *your own* dashboard, not an error page.
4. Signed in, no profile → an explanation, not a blank screen.
5. Staff role (`educator`, `specialist`, `school_admin`, `platform_admin`) with
   no authenticator enrolled → `/account/security`.

This is convenience, not security. Row-Level Security in the database is the
actual boundary.

## 7. Offline

Route splitting normally breaks offline apps. It does not here: the service
worker precaches every emitted chunk at build time (`globPatterns` in
`vite.config.ts`), so a lazy screen still opens with no connection.
